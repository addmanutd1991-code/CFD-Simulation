# CDU Airflow CFD

จำลองการไหลของลมร้อนจากคอยล์ร้อน (CDU) Daikin VRV 6A ในลานวางเครื่องแบบสามมิติ
หาการวนกลับของลมร้อน (hot-air recirculation) อุณหภูมิลมเข้าคอยล์รายเครื่อง และผลต่อ capacity
ทำงานในเบราว์เซอร์ทั้งหมด

## เปิดใช้งาน

**วิธีง่ายที่สุด** — ดับเบิลคลิก `dist/cdu-airflow-cfd.html` เปิดด้วย Chrome หรือ Edge
ไฟล์เดียวจบ ไม่ต้องติดตั้ง ไม่ต้องใช้เว็บเซิร์ฟเวอร์ และใช้งานออฟไลน์ได้ (คำนวณเธรดเดียว)

### เลือกเครื่องคำนวณ (ก่อนกด ▶ คำนวณ)

แผง **สภาพแวดล้อมและการคำนวณ → เครื่องคำนวณ** มีสองทางเลือก โปรแกรมจำค่าที่เลือกไว้กับเบราว์เซอร์

| ทางเลือก | ใช้อะไร | เปิดไฟล์ด้วยดับเบิลคลิก (`file://`) | เปิดผ่าน `http://` / `https://` |
|---|---|---|---|
| **CPU — WebAssembly** (ค่าเริ่มต้น) | แกนประมวลผลของ CPU | 1 เธรด | ทุกแกนของเครื่อง |
| **GPU — การ์ดจอ (WebGPU)** | การ์ดจอ ผ่าน compute shader | ใช้ได้ | ใช้ได้ |

- **GPU** ต้องใช้ Chrome / Edge รุ่น 113 ขึ้นไป (หรือเบราว์เซอร์อื่นที่มี WebGPU) และไดรเวอร์การ์ดจอที่รองรับ
  ถ้าเลือกไม่ได้ โปรแกรมบอกเหตุผลไว้ใต้ตัวเลือก ถ้าเตรียมการคำนวณบนการ์ดจอไม่สำเร็จ (เช่นหน่วยความจำการ์ดจอไม่พอ)
  จะคำนวณด้วย CPU แทนและแจ้งให้ทราบ
- GPU คำนวณด้วยเลขทศนิยม 32 บิต ส่วน CPU ใช้ 64 บิตระหว่างคำนวณ ผลจึงไม่ตรงกันทุกหลัก แต่ T ลมเข้ารายเครื่อง
  ตรงกันถึงทศนิยมสองตำแหน่งในกรณีทดสอบ (ดูหัวข้อ GPU ด้านล่าง)
- GPU ได้เปรียบชัดกับเมชใหญ่ (หลายแสนเซลล์ขึ้นไป) และการ์ดจอแยก — เมชเล็กหรือการ์ดจอในตัวรุ่นเก่า CPU หลายเธรดอาจเร็วกว่า
  ลองทั้งสองแบบกับงานของตัวเองแล้วเทียบเวลาที่แถบสถานะ

### ทำไม CPU หลายเธรดต้องเปิดผ่าน http(s)

การคำนวณหลายเธรดต้องให้ทุกเธรดอ่าน/เขียนหน่วยความจำก้อนเดียวกัน (`SharedArrayBuffer`) ตั้งแต่ปี 2018 (ช่องโหว่ Spectre)
เบราว์เซอร์ทุกตัวเปิดความสามารถนี้ให้เฉพาะหน้าที่ **cross-origin isolated** คือหน้าที่เซิร์ฟเวอร์ส่งส่วนหัว HTTP สองตัวมาด้วย
(`Cross-Origin-Opener-Policy` และ `Cross-Origin-Embedder-Policy`) หน้าที่เปิดจากไฟล์ในเครื่อง (`file://…`) ไม่ได้มาจากเซิร์ฟเวอร์
จึงไม่มีส่วนหัว และเบราว์เซอร์ไม่มีการตั้งค่าให้ผู้ใช้เปิดเองได้ — ไม่ใช่ข้อจำกัดของโปรแกรมนี้ และแก้จากในไฟล์ HTML ไม่ได้

"เปิดผ่าน http(s)" จึงหมายถึงให้แถบที่อยู่ของเบราว์เซอร์ขึ้นต้นด้วย `http://` หรือ `https://` แทน `file://` ทำได้สามวิธี:

1. **เซิร์ฟเวอร์ในเครื่อง (ใช้คนเดียว ออฟไลน์ได้)** — ติดตั้ง [Node.js](https://nodejs.org) แล้วในโฟลเดอร์โปรแกรมสั่ง
   `npm run serve` จากนั้นเปิด `http://localhost:8000/dist/cdu-airflow-cfd.html`
   เซิร์ฟเวอร์นี้รับเฉพาะการเชื่อมต่อจากเครื่องตัวเอง ไม่มีข้อมูลออกนอกเครื่อง ปิดด้วย Ctrl+C
2. **เซิร์ฟเวอร์ไฟล์อื่นที่มีอยู่แล้ว** เช่น `python -m http.server 8000` ในโฟลเดอร์ `dist/` แล้วเปิด
   `http://localhost:8000/cdu-airflow-cfd.html` — เซิร์ฟเวอร์แบบนี้ไม่ส่งส่วนหัวให้ แต่ไฟล์ `coi-sw.js` (service worker
   ที่อยู่ข้างไฟล์ HTML) จะเติมให้เองแล้วโหลดหน้าใหม่หนึ่งครั้ง
3. **เว็บโฮสต์ (ใช้ทั้งทีม)** — วางไฟล์ในโฟลเดอร์ `dist/` ทั้งสองไฟล์ (`cdu-airflow-cfd.html` และ `coi-sw.js`) ไว้บน GitHub Pages
   หรือเว็บภายในบริษัท แล้วเปิดด้วย `https://…` การคำนวณยังเกิดในเครื่องของผู้ใช้ทั้งหมด ไม่มีข้อมูลโปรเจกต์ส่งขึ้นเซิร์ฟเวอร์

ตรวจว่าได้ผล: แถบสถานะด้านล่างของโปรแกรมจะขึ้น `คำนวณด้วย WebAssembly N เธรด` หลังกด ▶ คำนวณ
ถ้าไม่สะดวกทั้งสามวิธี ให้เลือกเครื่องคำนวณเป็น **GPU** ซึ่งไม่มีเงื่อนไขนี้ ใช้ได้แม้ดับเบิลคลิกเปิดไฟล์

สำหรับพัฒนาโค้ด:

```
npm install
npm run serve        # เซิร์ฟเวอร์ในเครื่อง (tools/serve.mjs) แล้วเปิด http://localhost:8000
npm run build        # สร้าง dist/cdu-airflow-cfd.html ใหม่
npm run build:wasm   # คอมไพล์ src/kernels.c ใหม่ (ต้องมี clang + wasm-ld) — เฉพาะเมื่อแก้ kernels.c
npm test             # ทดสอบ solver: node tools/selftest.mjs <preset> <cell> <tEnd> [--uniform] [--threads=N] [--compare]
```

## ขั้นตอนการใช้งาน

1. **วางแบบ** — `+ CDU` คลิกบนพื้นเพื่อวางเครื่อง · `+ ผนัง / louver` คลิกจุดต่อจุดเพื่อลากผนังรอบลาน ·
   `+ อาคาร` คลิกสองมุม · `+ พื้น / หลังคา` คลิกสองมุมเพื่อวางแผ่นพื้นยก/หลังคา (ตั้งระดับ ความหนา % ช่องเปิดแบบตะแกรงได้;
   CDU ที่วางบนแผ่นจะยกฐานขึ้นไปบนผิวแผ่นอัตโนมัติ) · ระหว่างลากผนังพิมพ์ความยาวแล้วกด Enter ·
   ความยาวและมุมของผนังพิมพ์ค่าได้ที่แผงด้านขวา · หรือเลือก **ตัวอย่าง…** มุมขวาบน ·
   การวางและลากวัตถุจำกัดให้อยู่ภายในกริดแกนของพื้น (คลิกนอกขอบจะถูกดึงเข้ามาที่ขอบ) ·
   ขณะถือเครื่องมือ `+ CDU` / `+ ผนัง` คลิกโดนวัตถุเดิม (หรือกลางผนังเดิม) จะสลับไปเลือกวัตถุนั้นเพื่อแก้ไข แทนการวางซ้ำทับ
   · **คีย์ลัดสร้างโมเดล** (ใช้ได้แม้เปิดแป้นภาษาไทย · กด `?` หรือปุ่ม ⌨ ดูตารางทั้งหมด):
   `Ctrl+C` / `Ctrl+X` / `Ctrl+V` คัดลอก / ตัด / วาง ณ ตำแหน่งเมาส์ (วางซ้ำได้หลายครั้ง) ·
   `L` หรือ `Ctrl+L` ลากผนัง (Line) · `F8` หรือปุ่ม **Ortho** ล็อกผนัง/Move ตามแนวแกน X/Z (`Shift` สลับชั่วคราว) ·
   **`M` Move** แบบ AutoCAD: เลือกวัตถุ → คลิกจุดฐาน → คลิกจุดที่สอง หรือพิมพ์ระยะ + `Enter` ตามทิศเมาส์ ·
   **`O` Offset**: พิมพ์ระยะ + `Enter` → คลิกวัตถุ → คลิกฝั่งที่ต้องการ (ผนัง = สำเนาขนานห่างตามระยะ,
   CDU/อาคาร/พื้น = สำเนาเว้นช่องว่างระหว่างขอบตามระยะ เช่น ระยะ service) ทำต่อได้หลายครั้งจนกด `Esc` ·
   **`Shift+C` Copy**: เลือกวัตถุ → จุดฐาน → คลิกวางสำเนาได้หลายครั้ง (หรือพิมพ์ระยะ + `Enter`) จนกด `Esc` ·
   **`Shift+M` Mirror**: เลือกวัตถุ → คลิกสองจุดของเส้นสะท้อน → ได้สำเนาสะท้อน (ต้นฉบับคงเดิม, CDU กลับทิศหน้าเครื่องให้) ·
   **`Shift+R` Rotate**: เลือกวัตถุ → จุดฐาน → พิมพ์มุม (องศา, บวก = ทวนเข็มเมื่อมองแบบ Top, ลบ = ตามเข็ม) + `Enter` หรือคลิกตามทิศเมาส์
   (CDU หมุนได้ทีละ 90° · `F8` Ortho ปัดมุมทีละ 90°) ·
   ถ้าเลือกวัตถุไว้ก่อนเรียกคำสั่ง จะใช้วัตถุนั้นทันที (ข้ามขั้นเลือก) ·
   `Tab` / `Shift+Tab` เลือกวัตถุถัดไป/ก่อนหน้า · `Ctrl+D` ทำสำเนา · `R` หมุน 90° ทวนเข็ม (ทุกชนิดวัตถุ)
2. **ปรับแต่ง** — คลิกวัตถุแล้วแก้ที่แผงด้านขวา (รุ่น ทิศหน้าเครื่อง ฐาน Hood ความสูงและ % เปิดของ louver)
   - เลือก **หมวด** ก่อน (VRV / Split type) แล้วเลือกรุ่นในหมวดนั้น
   - **VRV 6A** (เป่าขึ้น): Hood แบบ **ตรง** หรือ **ท่อโค้ง 90°** — กำหนด **ความสูง** และ **ระยะยื่นออกด้านปากลม** ได้
     (เลือกทิศปากลม หน้า/หลัง/ซ้าย/ขวา — ซ้าย/ขวาใช้กับเครื่องโมดูลเดี่ยว) ท่อขึ้นจากเครื่อง โค้งด้านบน แล้วยื่นแนวนอนพ้นตัวเครื่อง
     ลมออกแนวนอนที่ปลายท่อ (หน้าตัดสูงเท่าความลึกเครื่อง 765 มม. ไม่เกินความสูง Hood)
   - **VRV IV S (RXMQ4–6)**, **VRV S Hi (RSUQ7–9)** และ **Split FTKB-A (RKB09/12AV2S)** (เป่าหน้า):
     **ทิศทางลมร้อนออกจากเครื่อง** ตรง หรือเบี่ยง 45° ขึ้น/ลง/ซ้าย/ขวา (มองจากด้านหน้าเครื่อง) — แทนใบเบี่ยงลมที่ติดกับเครื่อง
     ไม่วาดรูปทรง มีลูกศรสีส้มบอกทิศ · ใส่ Hood สี่เหลี่ยมครอบหน้ากากพัดลมได้ (กำหนดความยาว) · ลมเข้าด้านหลังและด้านซ้าย
   ลากเพื่อย้าย · `Ctrl+Z` เลิกทำ
3. **คำนวณ** — ตั้งอุณหภูมิอากาศ ลม (ความเร็วลมเข้าเท่ากันทั้งระนาบขอบต้นลม) ขนาดเซลล์ แล้วกด `▶ คำนวณ` — หยุดเองเมื่อผลนิ่ง
4. **อ่านผล** — ตัวเครื่องแต่ละโมดูลเปลี่ยนสีตาม T ลมเข้าเฉลี่ย (เขียว ≤ 40 °C · เหลือง > 40–46 °C · แดง > 46 °C ที่อากาศภายนอก 35 °C ปรับเกณฑ์ได้) ·
   ตารางรายเครื่อง (T ลมเข้า, ΔT, % ลมวนกลับ, capacity), ระนาบหน้าตัดสี, ผิวลมร้อน,
   อนุภาคลม, กราฟ T ลมเข้าตามเวลา, ข้อเสนอแนะการแก้ไข และตารางเปรียบเทียบทางเลือก
   · แผง **การแสดงผล**: เลือกรูปแบบกราฟิกบนระนาบหน้าตัด **Contour / Streamline / Vector** และตัวแปรที่ใช้ระบายสี
   (อุณหภูมิ ΔT ความเร็ว ความดันเทียบบรรยากาศ สัดส่วนลมร้อน) · ปรับ **ความทึบของวัตถุ** (ทึบ ↔ โปร่ง) เพื่อมองทะลุเครื่องและผนัง ·
   ภาพเคลื่อนไหว (อนุภาคลม แสงวิ่งตาม streamline) หยุดนิ่งเป็นค่าเริ่มต้น กด **▶ เล่นภาพเคลื่อนไหว** มุมขวาล่างเพื่อเล่น/หยุด ·
   **คลิกที่คอยล์ร้อน** เพื่อดู No. CDU รุ่นเครื่อง และอุณหภูมิลมกลับ (รวมรายโมดูล)
   · มุมมอง **3D / เหนือ / ใต้ / ออก / ตก** (3 มิติจากแต่ละทิศ) และ **Top** (ภาพฉายจากด้านบน) — ปุ่มลัด 1–6 · ปุ่ม **⛶ เต็มจอ** ยังมีแถบเครื่องมือ (+CDU / ผนัง / อาคาร / พื้น-หลังคา) และแผงแก้วัตถุให้ใช้ต่อ ·
   ความทึบของวัตถุปรับเฉพาะผนัง อาคาร พื้น/หลังคา — CDU ทึบเสมอ · Contour แสดงละเอียดกว่าเมช (แทรกค่าแบบ bilinear) ·
   **📷 Capture** (คีย์ `P`) เก็บภาพหลายมุมพร้อมแถบสี แก้คำบรรยายได้ และทุกภาพจะอยู่ในรายงาน HTML
5. **ส่งออก** — บันทึกโปรเจกต์ `.json`, ผลเป็น CSV, รายงาน HTML พร้อมภาพ 3D

## เมชและเวลาคำนวณ

เมชเป็นกริด rectilinear แบบ **ปรับความละเอียดอัตโนมัติ** (ค่าเริ่มต้น — `src/grid.js`): ใช้เซลล์ขนาดที่เลือกเฉพาะ
บริเวณที่ผลขึ้นกับความละเอียดจริง ๆ แล้วขยายเซลล์ออกไปไม่เกิน 20% ต่อเซลล์จนถึง 8 เท่า (ไม่เกิน 1 ม.) ที่ขอบโดเมน

- รอบ CDU 0.6 ม. และเหนือปากพัดลม 1.2 ม. — เซลล์ขนาด h วางบนแลตทิซเดียวกับเมชสม่ำเสมอ ตัวเครื่อง ผนัง และช่องว่าง
  รอบเครื่องจึงถูกแปลงเป็นเซลล์เหมือนเมชสม่ำเสมอทุกประการ
- ขอบผนัง / louver / อาคาร / แผ่นพื้นที่อยู่ใกล้เครื่อง (≤ 1 ม.) — ขนาด h เช่นกัน · ที่ไกลกว่านั้น 2h
- เครื่องที่ถูกล้อมด้วยของสูงกว่า (ช่องแคบระหว่างอาคาร คอกผนังสูง ใต้หลังคา ในระยะ 3 ม.) — คงขนาด h ในแนวดิ่ง
  ขึ้นไปถึงยอดสิ่งที่ล้อม เพราะลมร้อนวนกลับลงมาในช่องนั้น
- โดเมน ระยะเผื่อ และเงื่อนไขขอบเหมือนเมชสม่ำเสมอ เลือก **รูปแบบเมช → สม่ำเสมอ** ได้ถ้าต้องการเซลล์เท่ากันทั้งโดเมน

จำนวนเซลล์ของตัวอย่างสำเร็จรูป (สม่ำเสมอ → ปรับความละเอียดอัตโนมัติ):

| เซลล์ | ดาดฟ้า 6 ชุด | ช่องแคบระหว่างอาคาร | ลานพื้นดิน + ลม |
|---|---|---|---|
| 0.50 ม. | 36k → 26k | 40k → 26k | 36k → 25k |

## แบบจำลองเชิงตัวเลข (`src/solver.js`, `src/kernels.c`)

- Navier–Stokes แบบอัดตัวไม่ได้ บนกริด rectilinear แบบ staggered (MAC) + Boussinesq — เซลล์กว้างไม่เท่ากันได้
- โมเมนตัม: Semi-Lagrangian · ความดัน: projection + Red-Black SOR (warm start, ปรับรอบอัตโนมัติ)
- ความปั่นป่วน: Smagorinsky (Cs = 0.17, Δ = (Δx·Δy·Δz)^⅓)
- อุณหภูมิและ tracer: finite volume แบบอนุรักษ์ MUSCL/van Leer — สมดุลพลังงานตรวจได้ในแผงคุณภาพ
- CDU: หน้าคอยล์ (หลัง/ซ้าย/ขวา) ดูดลม, พัดลมด้านบนเป่าลม, ความร้อนทิ้งขึ้นกับ T ลมเข้าแบบป้อนกลับ
- Louver: ตัวกลางพรุน K = (1/(Cd·φ) − 1)²
- Δt จากอัตรา CFL สูงสุด max(|u|/Δx) ≤ 1.5 — เซลล์ใหญ่ที่อยู่ไกลเครื่องไม่ทำให้ Δt เล็กลง
- เกณฑ์ลู่เข้า: T ลมเข้าทุกเครื่องเปลี่ยน ≤ ±0.05 °C ระหว่างช่วง 10 วินาที และสมดุลพลังงาน 95–105%

### ความเร็วและหน่วยความจำ

ลูปหนักทั้งหมด (advection, turbulence, diffusion, projection/SOR, การพาอุณหภูมิ, residual) อยู่ใน `src/kernels.c`
คอมไพล์เป็น WebAssembly สองแบบและฝังไว้ใน `src/kernels-wasm.js`

- **หลายเธรด** — ทุกลูปแบ่งตามชั้น k ให้เธรดละช่วง เธรดช่วยงานเป็น Web Worker บนหน่วยความจำร่วม
  (SharedArrayBuffer + atomics) ใช้ทุกแกนของเครื่อง (เว้นหนึ่งแกนให้หน้าจอเมื่อมีมากกว่า 4 แกน, สูงสุด 16 เธรด)
  ผลรวมและค่าสูงสุดเก็บแยกตามชั้นแล้วรวมตามลำดับเดิมเสมอ ผลจึง **ตรงกันทุกบิตไม่ว่าจะใช้กี่เธรด**
  (`node tools/selftest.mjs rooftop 0.35 10 --compare` ตรวจให้)
  เบราว์เซอร์ให้ใช้หน่วยความจำร่วมเฉพาะหน้าที่เป็น cross-origin isolated: เมื่อเปิดผ่าน http(s)
  service worker `coi-sw.js` จะเติมส่วนหัว COOP/COEP ให้เองแล้วโหลดหน้าใหม่หนึ่งครั้ง ไม่ต้องตั้งค่าเซิร์ฟเวอร์
  เปิดไฟล์ด้วย `file://` ทำไม่ได้ จึงคำนวณเธรดเดียว
- **หน่วยความจำ ≈ 75 ไบต์ต่อเซลล์** (เดิม 112 + สำเนานอก WebAssembly อีก 16): ฟลักซ์ของการพาอุณหภูมิส่งต่อผ่านบัฟเฟอร์
  ขนาดหนึ่งระนาบแทนอาร์เรย์สะสมเต็มกริด, ความเร็วที่กำหนดที่ขอบเก็บเป็นรายการเฉพาะหน้า, บัฟเฟอร์ความเร็วสลับแทนการคัดลอก
  รวมกับเมชที่เล็กลง ตัวอย่างดาดฟ้าที่เซลล์ 0.10 ม. ใช้ราว 64 MB จากเดิมราว 550 MB — เพดาน 4 GB ของ WebAssembly
  จึงรองรับงานที่ใหญ่กว่าเดิมมาก
- เมชใหญ่ส่งสนามค่าไปแสดงผลห่างขึ้น (ราว 0.4 วินาทีต่อล้านเซลล์) ไม่ให้การคัดลอกถ่วงการคำนวณ

### GPU (`src/gpu-solver.js`)

เครื่องคำนวณแบบ GPU เป็น solver ชุดเดียวกันที่เขียนเป็น compute shader (WGSL) ของ WebGPU — สมการ กริด เงื่อนไขขอบ
และเกณฑ์ลู่เข้าเหมือนแบบ CPU (ใช้การเตรียมกริด `src/prep.js` และการติดตามผล `src/monitor.js` ร่วมกัน) ต่างกันที่

- เลขทศนิยม 32 บิตทั้งหมด อุณหภูมิเก็บเป็นส่วนเกินจากอากาศภายนอก (T − T∞) เพื่อรักษาความละเอียด
- ทั้งสเต็ปส่งให้การ์ดจอเป็นชุดคำสั่งเดียว แล้วอ่านผลรวมขนาดเล็กกลับมาครั้งเดียวต่อสเต็ป Δt จำนวนสเต็ปย่อย
  และอุณหภูมิลมเป่าของ CDU จึงใช้ค่าจากสเต็ปก่อนหน้า (ช้าไปหนึ่งสเต็ป ≈ 0.02–0.06 s)
- หน่วยความจำบนการ์ดจอ ≈ 112 ไบต์ต่อเซลล์ และบัฟเฟอร์ใหญ่สุด 16 ไบต์ต่อเซลล์ต้องไม่เกินขีดจำกัดของการ์ดจอ

ผลเทียบกับ CPU (`tools/gputest.html` — เปิดผ่าน `npm run serve`): สนามความเร็วและความดันสเต็ปแรก ๆ ต่างกันระดับ 10⁻⁶
และ T ลมเข้าเฉลี่ยตามเวลารายเครื่องต่างกันไม่เกิน 0.01 K ในตัวอย่างดาดฟ้า ช่องแคบ และลานพื้นดินมีลม (เซลล์ 0.5 ม.)
การทดสอบนี้ทำบน WebGPU แบบจำลองด้วยซอฟต์แวร์ (ไม่มีการ์ดจอจริง) จึงยืนยันได้เฉพาะความถูกต้อง
**ยังไม่ได้วัดความเร็วบนการ์ดจอจริง**

ตารางรุ่นใน `src/models.js` (kW, อัตราลม, ขนาด, ชุดผสม 8–78 HP) มาจาก catalog EDTRTH342529A (VRV 6A),
EDTRMT332049 (VRV IV S: RXMQ4AVE / 5BVM / 6BVM — 990 × 940 × 320 มม.) และ EDTRMT332104A (VRV S Hi: RSUQ7/8/9AYM — 870 × 1,100 × 460 มม.)
และ EDTTH042558 (Split FTKB-A: คอยล์ร้อน RKB09AV2S 2.7 kW / RKB12AV2S 3.6 kW — 461 × 650 × 244 มม., EER ใช้ COP จาก catalog 3.09 / 3.10)
ตำแหน่งและขนาดหน้ากากพัดลมของรุ่นเป่าหน้าประมาณจากแบบ Dimensions

รุ่นเป่าหน้าบนกริด: ลมออกเป็นหน้า u/w ด้านหน้าเครื่อง (หรือปลาย Hood) · ทิศทางลมร้อนเบี่ยง 45° ไม่มีรูปทรงบนกริด —
กำหนดความเร็วตามทิศเบี่ยงเท่ากับความเร็วพุ่ง ที่หน้าเซลล์ระหว่างเซลล์อากาศชั้นแรกหน้าปากลม (เหมือนแถวใบเกล็ดบาง ๆ ติดหน้าเครื่อง)
ทดสอบแล้วลำลมร้อนเอียง 38–43° จากแนวตั้งฉากหน้าเครื่อง (เซลล์ 0.1 ม.) · ปากลมต้องกว้างอย่างน้อย 2 เซลล์
เครื่อง Split มีขนาดเล็ก (ลึก 244 มม.) ควรใช้เซลล์ ≤ 0.1 ม.
ส่วน EER 3.5 ของ VRV และ capacity ลดลง 2 %/°C เป็นค่าประมาณ แก้ได้ในโปรแกรม
ผลใช้เปรียบเทียบผังการวางเครื่อง ไม่ใช่ผลรับรองทางวิศวกรรม
