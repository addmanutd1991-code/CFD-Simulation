# CDU Airflow CFD

จำลองการไหลของลมร้อนจากคอยล์ร้อน (CDU) Daikin VRV 6A ในลานวางเครื่องแบบสามมิติ
หาการวนกลับของลมร้อน (hot-air recirculation) อุณหภูมิลมเข้าคอยล์รายเครื่อง และผลต่อ capacity
ทำงานในเบราว์เซอร์ทั้งหมด · หน้าจอมีภาษา **ไทย / English** และธีม **มืด / สว่าง / ตามระบบ**

## เปิดใช้งาน

**วิธีง่ายที่สุด** — ดับเบิลคลิก `dist/cdu-airflow-cfd.html` เปิดด้วย Chrome หรือ Edge
ไฟล์เดียวจบ ไม่ต้องติดตั้ง ไม่ต้องใช้เว็บเซิร์ฟเวอร์ และใช้งานออฟไลน์ได้ (คำนวณเธรดเดียว)

### เลือกเครื่องคำนวณ (ก่อนกด คำนวณ)

แผงด้านขวา แท็บ **ตั้งค่า → เครื่องคำนวณ** มีสองทางเลือก โปรแกรมจำค่าที่เลือกไว้กับเบราว์เซอร์

| ทางเลือก | ใช้อะไร | เปิดไฟล์ด้วยดับเบิลคลิก (`file://`) | เปิดผ่าน `http://` / `https://` |
|---|---|---|---|
| **CPU — WebAssembly** (ค่าเริ่มต้น) | แกนประมวลผลของ CPU | 1 เธรด | ทุกแกนของเครื่อง |
| **GPU — การ์ดจอ (WebGPU)** | การ์ดจอ ผ่าน compute shader | ใช้ได้ | ใช้ได้ |

- **GPU** ต้องใช้ Chrome / Edge รุ่น 113 ขึ้นไป (หรือเบราว์เซอร์อื่นที่มี WebGPU) และไดรเวอร์การ์ดจอที่รองรับ
  ถ้าเลือกไม่ได้ โปรแกรมบอกเหตุผลไว้ใต้ตัวเลือก ถ้าเตรียมการคำนวณบนการ์ดจอไม่สำเร็จ (เช่นหน่วยความจำการ์ดจอไม่พอ)
  จะคำนวณด้วย CPU แทนและแจ้งให้ทราบ
- GPU คำนวณด้วยเลขทศนิยม 32 บิต ส่วน CPU ใช้ 64 บิตระหว่างคำนวณ ผลจึงไม่ตรงกันทุกหลัก แต่ T ลมเข้ารายเครื่อง
  ตรงกันถึงทศนิยมสองตำแหน่งในกรณีทดสอบ (ดูหัวข้อ GPU ด้านล่าง)
- GPU ได้เปรียบชัดกับเมชใหญ่ (หลายแสนเซลล์ขึ้นไป) และการ์ดจอแยก — เมชเล็กหรือการ์ดจอในตัวรุ่นเก่า CPU หลายเธรดอาจเร็วกว่า
  ลองทั้งสองแบบกับงานของตัวเองแล้วเทียบเวลาที่แถบสถานะ

### ทำไม CPU หลายเธรดต้องเปิดผ่าน http(s)

การคำนวณหลายเธรดต้องให้ทุกเธรดอ่าน/เขียนหน่วยความจำก้อนเดียวกัน (`SharedArrayBuffer`) ตั้งแต่ปี 2018 (ช่องโหว่ Spectre)
เบราว์เซอร์ทุกตัวเปิดความสามารถนี้ให้เฉพาะหน้าที่ **cross-origin isolated** คือหน้าที่เซิร์ฟเวอร์ส่งส่วนหัว HTTP สองตัวมาด้วย
(`Cross-Origin-Opener-Policy` และ `Cross-Origin-Embedder-Policy`) หน้าที่เปิดจากไฟล์ในเครื่อง (`file://…`) ไม่ได้มาจากเซิร์ฟเวอร์
จึงไม่มีส่วนหัว และเบราว์เซอร์ไม่มีการตั้งค่าให้ผู้ใช้เปิดเองได้ — ไม่ใช่ข้อจำกัดของโปรแกรมนี้ และแก้จากในไฟล์ HTML ไม่ได้

"เปิดผ่าน http(s)" จึงหมายถึงให้แถบที่อยู่ของเบราว์เซอร์ขึ้นต้นด้วย `http://` หรือ `https://` แทน `file://` ทำได้สามวิธี:

1. **เซิร์ฟเวอร์ในเครื่อง (ใช้คนเดียว ออฟไลน์ได้)** — ติดตั้ง [Node.js](https://nodejs.org) แล้วในโฟลเดอร์โปรแกรมสั่ง
   `npm run serve` จากนั้นเปิด `http://localhost:8000/dist/cdu-airflow-cfd.html`
   เซิร์ฟเวอร์นี้รับเฉพาะการเชื่อมต่อจากเครื่องตัวเอง ไม่มีข้อมูลออกนอกเครื่อง ปิดด้วย Ctrl+C
2. **เซิร์ฟเวอร์ไฟล์อื่นที่มีอยู่แล้ว** เช่น `python -m http.server 8000` ในโฟลเดอร์ `dist/` แล้วเปิด
   `http://localhost:8000/cdu-airflow-cfd.html` — เซิร์ฟเวอร์แบบนี้ไม่ส่งส่วนหัวให้ แต่ไฟล์ `coi-sw.js` (service worker
   ที่อยู่ข้างไฟล์ HTML) จะเติมให้เองแล้วโหลดหน้าใหม่หนึ่งครั้ง
3. **เว็บโฮสต์ (ใช้ทั้งทีม)** — วางไฟล์ในโฟลเดอร์ `dist/` ทั้งสองไฟล์ (`cdu-airflow-cfd.html` และ `coi-sw.js`) ไว้บน GitHub Pages
   หรือเว็บภายในบริษัท แล้วเปิดด้วย `https://…` การคำนวณยังเกิดในเครื่องของผู้ใช้ทั้งหมด ไม่มีข้อมูลโปรเจกต์ส่งขึ้นเซิร์ฟเวอร์

ตรวจว่าได้ผล: แถบสถานะด้านล่างของโปรแกรมจะขึ้น `คำนวณด้วย WebAssembly N เธรด` หลังกด คำนวณ
ถ้าไม่สะดวกทั้งสามวิธี ให้เลือกเครื่องคำนวณเป็น **GPU** ซึ่งไม่มีเงื่อนไขนี้ ใช้ได้แม้ดับเบิลคลิกเปิดไฟล์

สำหรับพัฒนาโค้ด:

```
npm install
npm run serve        # เซิร์ฟเวอร์ในเครื่อง (tools/serve.mjs) แล้วเปิด http://localhost:8000
npm run build        # สร้าง dist/cdu-airflow-cfd.html ใหม่
npm run build:wasm   # คอมไพล์ src/kernels.c ใหม่ (ต้องมี clang + wasm-ld) — เฉพาะเมื่อแก้ kernels.c
npm test             # ทดสอบ solver: node tools/selftest.mjs <preset> <cell> <tEnd> [--uniform] [--threads=N] [--compare]
```

### ล็อกโมเดลหลังคำนวณ

เมื่อกด **คำนวณ** แล้ว โมเดลจะถูกล็อก คลิกโดนวัตถุในภาพได้แค่เลือกดูค่า ย้าย แก้ ลบ หรือวางวัตถุใหม่ไม่ได้
ผลคำนวณจึงไม่หายเพราะคลิกพลาด ถ้าต้องการปรับแบบให้กดปุ่ม **แก้ไขโมเดล** ที่แถบบน (หรือในแผงคุณสมบัติ)
ผลเดิมยังอยู่จนกว่าจะแก้แบบจริง และกด **ล็อกโมเดล** เพื่อล็อกกลับได้ การลากวัตถุต้องขยับเมาส์เกิน 5 พิกเซล
คลิกที่มือสั่นเล็กน้อยจึงไม่นับเป็นการย้าย

## ขั้นตอนการใช้งาน

1. **วางแบบ** — เครื่องมือ `CDU` (แถบซ้าย) คลิกบนพื้นเพื่อวางเครื่อง · `ผนัง/louver` คลิกจุดต่อจุดเพื่อลากผนังรอบลาน ·
   `อาคาร` คลิกสองมุม · `พื้น/หลังคา` คลิกสองมุมเพื่อวางแผ่นพื้นยก/หลังคา (ตั้งระดับ ความหนา % ช่องเปิดแบบตะแกรงได้;
   CDU ที่วางบนแผ่นจะยกฐานขึ้นไปบนผิวแผ่นอัตโนมัติ) · ระหว่างลากผนังพิมพ์ความยาวแล้วกด Enter ·
   ความยาวและมุมของผนังพิมพ์ค่าได้ที่แผงด้านขวา · หรือเปิด **ไฟล์ → ตัวอย่างสำเร็จรูป / กรณีศึกษา** ที่แถบบน ·
   การวางและลากวัตถุจำกัดให้อยู่ภายในกริดแกนของพื้น (คลิกนอกขอบจะถูกดึงเข้ามาที่ขอบ) ·
   ขณะถือเครื่องมือ `CDU` / `ผนัง/louver` คลิกโดนวัตถุเดิม (หรือกลางผนังเดิม) จะสลับไปเลือกวัตถุนั้นเพื่อแก้ไข แทนการวางซ้ำทับ
   · **คีย์ลัดสร้างโมเดล** (ใช้ได้แม้เปิดแป้นภาษาไทย · กด `?` หรือปุ่ม **คีย์ลัด** ที่แถบซ้ายเพื่อดูตารางทั้งหมด · คำสั่ง Move / Copy / Offset / Mirror / Rotate / Pull เรียกด้วยเมาส์ได้จากปุ่มเล็กกลุ่ม **แก้ไข** ที่แถบซ้าย):
   `Ctrl+C` / `Ctrl+X` / `Ctrl+V` คัดลอก / ตัด / วาง ณ ตำแหน่งเมาส์ (วางซ้ำได้หลายครั้ง) ·
   `L` หรือ `Ctrl+L` ลากผนัง (Line) · `F8` หรือปุ่ม **Ortho** ล็อกผนัง/Move ตามแนวแกน X/Z (`Shift` สลับชั่วคราว) ·
   **`M` Move** แบบ AutoCAD: เลือกวัตถุ → คลิกจุดฐาน → คลิกจุดที่สอง หรือพิมพ์ระยะ + `Enter` ตามทิศเมาส์ ·
   **`O` Offset**: พิมพ์ระยะ + `Enter` → คลิกวัตถุ → คลิกฝั่งที่ต้องการ (ผนัง = สำเนาขนานห่างตามระยะ,
   CDU/อาคาร/พื้น = สำเนาเว้นช่องว่างระหว่างขอบตามระยะ เช่น ระยะ service) ทำต่อได้หลายครั้งจนกด `Esc` ·
   **`S` Pull**: ยืด/หด ผนัง · louver · อาคาร · พื้น-หลังคา — เลือกวัตถุ → คลิกปลายผนังหรือด้านของอาคารที่จะขยับ (เส้นประบอกจุดที่ถูกเลือก)
   → ลากแล้วคลิกตำแหน่งใหม่ หรือพิมพ์ระยะ + `Enter` (ค่าบวก = ไปทางที่เมาส์ชี้, ค่าลบ = หด) ด้านตรงข้ามอยู่กับที่ ·
   **`Shift+C` Copy**: เลือกวัตถุ → จุดฐาน → คลิกวางสำเนาได้หลายครั้ง (หรือพิมพ์ระยะ + `Enter`) จนกด `Esc` ·
   **`Shift+M` Mirror**: เลือกวัตถุ → คลิกสองจุดของเส้นสะท้อน → ได้สำเนาสะท้อน (ต้นฉบับคงเดิม, CDU กลับทิศหน้าเครื่องให้) ·
   **`Shift+R` Rotate**: เลือกวัตถุ → จุดฐาน → พิมพ์มุม (องศา, บวก = ทวนเข็มเมื่อมองแบบ Top, ลบ = ตามเข็ม) + `Enter` หรือคลิกตามทิศเมาส์
   (CDU หมุนได้ทีละ 90° · `F8` Ortho ปัดมุมทีละ 90°) ·
   ถ้าเลือกวัตถุไว้ก่อนเรียกคำสั่ง จะใช้วัตถุนั้นทันที (ข้ามขั้นเลือก) ·
   `Tab` / `Shift+Tab` เลือกวัตถุถัดไป/ก่อนหน้า · `Ctrl+D` ทำสำเนา · `R` หมุน 90° ทวนเข็ม (ทุกชนิดวัตถุ)
2. **ปรับแต่ง** — คลิกวัตถุแล้วแก้ที่แผงด้านขวา (รุ่น ทิศหน้าเครื่อง ฐาน Hood ความสูงและ % เปิดของ louver)
   - เลือก **หมวด** ก่อน (VRV / Split type) แล้วเลือกรุ่นในหมวดนั้น
   - **VRV 6A** (เป่าขึ้น): Hood แยกรายโมดูล แบบ **ตรง** (ท่อสี่เหลี่ยมขนาดเท่าโมดูล ลมออกขึ้นทั้งหน้าตัด) หรือ
     **ท่อโค้ง 90°** — กำหนด **ความสูง** และ **ระยะยื่นออกด้านปากลม** ได้
     (เลือกทิศปากลม หน้า/หลัง/ซ้าย/ขวา — ซ้าย/ขวาใช้กับเครื่องโมดูลเดี่ยว) ท่อขึ้นจากเครื่อง โค้งด้านบน แล้วยื่นแนวนอนพ้นตัวเครื่อง
     ลมออกแนวนอนที่ปลายท่อ (หน้าตัดสูงเท่าความลึกเครื่อง 765 มม. ไม่เกินความสูง Hood)
   - **VRV IV S (RXMQ4–6)**, **VRV S Hi (RSUQ7–9)** และ **Split FTKB-A (RKB09/12AV2S)** และคอยล์ร้อน Split **RKB15–24ZV2S, RKC-ZV2S, RKD-ZV2S, RKF-YV2S, RKM-YV2S, RKQ-YV2S, RKZ-YV2S, RKE-YV2S** และ CDU **Sky Air Premium RZF-DV2S/DY2S (รวม RZFS38DY2S)** และ **Sky Air Standard RZFC-EV2S/EY2S** (เป่าหน้า):
     **ทิศทางลมร้อนออกจากเครื่อง** ตรง หรือเบี่ยง 45° ขึ้น/ลง/ซ้าย/ขวา (มองจากด้านหน้าเครื่อง) — แทนใบเบี่ยงลมที่ติดกับเครื่อง
     ไม่วาดรูปทรง มีลูกศรสีส้มบอกทิศ · ใส่ Hood สี่เหลี่ยมครอบหน้ากากพัดลมได้ (กำหนดความยาว) · ลมเข้าด้านหลังและด้านซ้าย
   ลากเพื่อย้าย · `Ctrl+Z` เลิกทำ
3. **คำนวณ** — ตั้งอุณหภูมิอากาศ ลม (ความเร็วลมเข้าเท่ากันทั้งระนาบขอบต้นลม) ขนาดเซลล์ ที่แท็บ **ตั้งค่า** ของแผงขวา แล้วกด **คำนวณ** มุมขวาบน — หยุดเองเมื่อผลนิ่ง
4. **อ่านผล** — ตัวเครื่องแต่ละโมดูลเปลี่ยนสีตาม T ลมเข้าเฉลี่ย (เขียว ≤ 40 °C · เหลือง > 40–46 °C · แดง > 46 °C ที่อากาศภายนอก 35 °C ปรับเกณฑ์ได้) ·
   ระนาบหน้าตัดสี ผิวลมร้อน และอนุภาคลมในภาพ 3D · หน้า **ผลลัพธ์**: ตารางรายเครื่อง (T ลมเข้า, ΔT, % ลมวนกลับ, capacity),
   กราฟ T ลมเข้าตามเวลา, ข้อเสนอแนะการแก้ไข และตารางเปรียบเทียบทางเลือก
   · แท็บ **แสดงผล** ของแผงขวา: เลือกรูปแบบกราฟิกบนระนาบหน้าตัด **Contour / Streamline / Vector** และตัวแปรที่ใช้ระบายสี
   (อุณหภูมิ ΔT ความเร็ว ความดันเทียบบรรยากาศ สัดส่วนลมร้อน) · ปรับ **ความทึบของวัตถุ** (ทึบ ↔ โปร่ง) เพื่อมองทะลุเครื่องและผนัง ·
   ภาพเคลื่อนไหว (อนุภาคลม แสงวิ่งตาม streamline) หยุดนิ่งเป็นค่าเริ่มต้น กด **เล่นภาพเคลื่อนไหว** มุมขวาล่างของภาพเพื่อเล่น/หยุด ·
   **คลิกที่คอยล์ร้อน** เพื่อดู No. CDU รุ่นเครื่อง และอุณหภูมิลมกลับ (รวมรายโมดูล)
   · มุมมอง **3D / เหนือ / ใต้ / ออก / ตก** (3 มิติจากแต่ละทิศ) **Top** (ภาพฉายจากด้านบน) และ **Iso** (Isometric ภาพฉายจากมุม +X +Y +Z) — ปุ่มลัด 1–7 · **แกน X-Y-Z มุมขวาล่าง** หมุนตามกล้อง คลิกปลายแกน **+X / −X / +Y / −Y / +Z / −Z** เพื่อมองตามแกน (ภาพฉาย) คลิกจุดกลางเพื่อกลับมุมมอง 3D · ปุ่ม **เต็มจอ** ขยายทั้งโปรแกรม — แถบเครื่องมือ แผงแก้วัตถุ และปุ่มคำนวณยังใช้ต่อได้ ·
   ความทึบของวัตถุปรับเฉพาะผนัง อาคาร พื้น/หลังคา — CDU ทึบเสมอ · Contour แสดงละเอียดกว่าเมช (แทรกค่าแบบ bilinear) ·
   **Capture** (ปุ่มรูปกล้องบนภาพ, คีย์ `P`) เก็บภาพหลายมุมพร้อมแถบสี แก้คำบรรยายได้ที่หน้า **ผลลัพธ์** และทุกภาพจะอยู่ในรายงาน HTML
5. **ส่งออก** — บันทึกโปรเจกต์ `.json`, ผลเป็น CSV, รายงาน HTML พร้อมภาพ 3D

ทฤษฎี สมการ และเกณฑ์ทั้งหมดอยู่ในหน้า **คู่มือ** ภายในโปรแกรม

## ลมตามความสูง และลม 4 ทิศ

แท็บ **ตั้งค่า → สภาพแวดล้อม → โปรไฟล์ลมตามความสูง** (`src/wind.js`) — ความเร็วลมที่ขอบต้นลม
V(z) = V<sub>ref</sub> · (z / z<sub>ref</sub>)<sup>α</sup> โดย z = ระดับพื้นที่วางเครื่องเหนือพื้นดิน + ความสูงในโดเมน

| สภาพพื้นที่ | α |
|---|---|
| สม่ำเสมอทุกระดับ (แบบเดิม — ค่าเริ่มต้นของโปรเจกต์เดิมและตัวอย่างสำเร็จรูป) | 0 |
| พื้นที่โล่ง | 0.14 |
| ชานเมือง | 0.22 |
| เมือง | 0.30 |
| ใจกลางเมือง ตึกสูงหนาแน่น | 0.40 |

- **ความเร็วลม** ที่กรอกคือค่าที่ **ความสูงอ้างอิง** (ค่าเริ่มต้น 10 ม. เหนือพื้นดิน ตามข้อมูลสถานีอุตุนิยมวิทยา)
- **ระดับพื้นที่วางเครื่องเหนือพื้นดิน** — เช่น ดาดฟ้าอาคาร 10 ชั้น ≈ 35 ม. ลมบนดาดฟ้าจึงแรงกว่าค่าที่ 10 ม.
- ใกล้พื้นดินกว่า 1 ม. ใช้ค่าที่ 1 ม. (power law ให้ความเร็วเข้าใกล้ศูนย์ที่พื้น) · แผงแสดงความเร็วที่ 0.5 ม. 2 ม. และยอดโดเมนให้ตรวจ
- ทดสอบจาก command line: `node tools/selftest.mjs rooftop 0.5 120 --wind=3:90:urban:30` (ความเร็ว : ทิศ : สภาพพื้นที่ : ระดับพื้น)

ปุ่ม **คำนวณลม 4 ทิศ…** (ใต้ค่าตั้งลม) เปิดหน้าต่าง Batch ที่เลือกลม N / E / S / W ไว้แล้ว — ผลและรายงานมี
**ตาราง T ลมเข้าเฉลี่ยรายเครื่อง ลม 4 ทิศ** พร้อมเน้นทิศที่แย่ที่สุดของแต่ละเครื่อง

## Batch — รันหลายทางเลือกต่อกันอัตโนมัติ

หน้า **ผลลัพธ์ → Batch…** (`src/batch.js`) — เลือกตัวแปรที่ปรับ แต่ละตัวกำหนดวัตถุเป้าหมาย (ชิ้นเดียว หรือทั้งหมด) และค่าที่จะลอง

| ตัวแปร | ปรับอะไร | "ทั้งหมด" หมายถึง |
|---|---|---|
| % เปิดของ louver / ระแนง | `louver` ของผนัง | ทุกผนังที่เป็น louver อยู่แล้ว |
| Hood | `duct` ของ CDU (รุ่นเป่าขึ้น = ความสูง, รุ่นเป่าหน้า = ความยาว, 0 = ไม่มี) | ทุก CDU |
| ความสูงผนัง | `height` ของผนัง | ทุกผนัง |
| ยกฐานเครื่อง | ระยะฐาน CDU เหนือผิวที่วางอยู่ (พื้น หรือแผ่นพื้น/หลังคา) | ทุก CDU |
| ลม 4 ทิศ | ทิศลม N / E / S / W ที่ความเร็วที่กำหนด (+ กรณีไม่มีลม) | — |

- ทุกชุดค่าผสมเป็น 1 case (สูงสุด 48) เช่น louver 50/70/90 % × ลม 4 ทิศ = 12 case
- คำนวณทีละ case จนลู่เข้า (หรือถึงเพดานเวลา) แล้วเก็บผล ข้อสังเกต และภาพ 2 มุม (มุมมองปัจจุบัน + Top พร้อมแถบสี)
  ก่อนเริ่ม case ถัดไป — ตั้งมุมมอง ตัวแปรที่ระบายสี และระนาบหน้าตัดก่อนกดเริ่ม · จบแล้วคืนแบบตั้งต้น
- การ์ด **ผล Batch** มีสรุปรายการ (ΔT สูงสุด เครื่องที่แย่สุด ΔT เฉลี่ย) ปุ่ม **รายงาน** แยกราย case และ **เปิด** แบบของ case นั้น ·
  **รายงานรวม** (ไฟล์เดียว: ตารางสรุป + ตารางลม 4 ทิศ + รายละเอียดทุก case) · **รายงานแยกทุก Case** (ไฟล์ละ case) · **CSV** รายเครื่องทุก case
- ทุก case ขึ้นในตาราง **เปรียบเทียบทางเลือก** ด้วย · กด **รีเซ็ตผล** ระหว่างรันเพื่อยกเลิก (case ที่เสร็จแล้วยังอยู่)
- ผล Batch อยู่ในแท็บเบราว์เซอร์นี้เท่านั้น — ดาวน์โหลดรายงานก่อนปิดหน้า

## นำเข้าแบบ DXF เป็นฉากหลัง

**ไฟล์ → นำเข้าแบบ DXF (ฉากหลัง)…** (`src/dxf.js`) — อ่าน DXF แบบ ASCII: LINE, LWPOLYLINE / POLYLINE (รวมส่วนโค้ง bulge), ARC, CIRCLE
และบล็อก (INSERT ซ้อนกันได้ สเกล/หมุน) · ข้าม TEXT, DIMENSION, HATCH, SPLINE, ELLIPSE · ไฟล์ binary ไม่รองรับ

- **หน่วย** จาก `$INSUNITS` ของไฟล์ (ถ้าไม่ระบุจะเดาจากขนาดแบบ — ตรวจและเปลี่ยนได้) · แกน X ของแบบ = ทิศตะวันออก, แกน Y = ทิศเหนือ
- วางมุมซ้ายบนของแบบไว้ที่ (0, 0) · เลื่อน x / z และหมุนได้ · แสดง/ซ่อนรายเลเยอร์ และปรับความเข้ม
- **ดูดจุดปลายเส้น** — ขณะวาดผนังหรือวางวัตถุ (และขณะลาก) เมาส์ดูดเข้าจุดปลายเส้นที่ใกล้ (วงสีส้ม) ได้ค่าตรงตามแบบไม่ปัดเศษ · กด `Alt` ค้างเพื่อไม่ดูด ·
  พื้นที่ที่วางวัตถุได้ขยายครอบแบบทั้งแผ่น
- **แปลงเลเยอร์เป็นวัตถุ** — เลือก "แปลงเป็น" รายเลเยอร์: ผนังทึบ / louver (ทุกช่วงของเส้นเป็นผนัง 1 ชิ้น ช่วงที่อยู่แนวเดียวกันรวมกัน ตัดช่วงสั้นกว่า 0.1 ม.) ·
  อาคาร / CDU (เฉพาะสี่เหลี่ยมผืนผ้าปิด — อาคารหมุนตามแบบ, CDU ใช้รุ่นที่วางล่าสุด หันหน้า +z หรือ +x ตามด้านยาว ตรวจทิศหน้าเครื่องหลังแปลง) ·
  กำหนดความสูง/ความหนาผนัง % louver และความสูงอาคาร · ย้อนกลับด้วย `Ctrl+Z`
- แบบฉากหลังไม่อยู่ในการคำนวณ จำไว้กับเบราว์เซอร์ และบันทึกลงไฟล์โปรเจกต์ `.json` (ฟิลด์ `underlay`)

## เมชและเวลาคำนวณ

เมชเป็นกริด rectilinear แบบ **ปรับความละเอียดอัตโนมัติ** (ค่าเริ่มต้น — `src/grid.js`): ใช้เซลล์ขนาดที่เลือกเฉพาะ

## แบบจำลองเชิงตัวเลข (`src/solver.js`, `src/kernels.c`)

- Navier–Stokes แบบอัดตัวไม่ได้ บนกริด rectilinear แบบ staggered (MAC) + Boussinesq — เซลล์กว้างไม่เท่ากันได้
- โมเมนตัม: Semi-Lagrangian · ความดัน: projection + Red-Black SOR (warm start, ปรับรอบอัตโนมัติ)
- ความปั่นป่วน: Smagorinsky (Cs = 0.17, Δ = (Δx·Δy·Δz)^⅓)
- อุณหภูมิและ tracer: finite volume แบบอนุรักษ์ MUSCL/van Leer — สมดุลพลังงานตรวจได้ในแผงคุณภาพ
- CDU: หน้าคอยล์ (หลัง/ซ้าย/ขวา) ดูดลม, พัดลมด้านบนเป่าลม, ความร้อนทิ้งขึ้นกับ T ลมเข้าแบบป้อนกลับ
- Louver: ตัวกลางพรุน K = (1/(Cd·φ) − 1)²
- Δt จากอัตรา CFL สูงสุด max(|u|/Δx) ≤ 1.5 — เซลล์ใหญ่ที่อยู่ไกลเครื่องไม่ทำให้ Δt เล็กลง
- เกณฑ์ลู่เข้า: T ลมเข้าทุกเครื่องเปลี่ยน ≤ ±0.05 / 0.1 / 0.2 °C (เข้มงวด / มาตรฐาน — ค่าเริ่มต้น / เร็ว) ระหว่างช่วง 10 วินาที
  และสมดุลพลังงาน 95–105% (เร็ว: 92–108%) ผ่านต่อเนื่อง 6 ครั้ง (เร็ว: 4)

### เงื่อนไขหยุดการคำนวณ

แท็บ **ตั้งค่า → เมชและการคำนวณ → หยุดคำนวณเมื่อ** (`src/monitor.js` → `limitReached`)

| ตัวเลือก | หยุดเมื่อ |
|---|---|
| **ลู่เข้าแล้ว** (ค่าเริ่มต้น) | ผ่านเกณฑ์ลู่เข้าที่เลือก หรือถึงเพดานเวลาจำลอง (ขั้นสูง, ค่าเริ่มต้น 1,800 s) |
| **ครบเวลาจำลอง** | เวลาในแบบจำลองครบตามที่กำหนด (วินาที) |
| **ครบจำนวนรอบ** | จำนวน time step ครบตามที่กำหนด |
| **ครบเวลาคำนวณจริง** | ใช้เวลาคำนวณจริงครบตามที่กำหนด (นาที — ไม่นับช่วงหยุดชั่วคราว) |

- สามแบบหลังเลือก **หยุดก่อนถ้าลู่เข้าแล้ว** ได้ (ค่าเริ่มต้น) · เว้นช่องว่างไว้ = ใช้ค่าแนะนำ
- **ค่าแนะนำ**: เวลาจำลอง T ≈ 60 + 3·L / U (L = เส้นทแยงโดเมนแนวนอน, U = ความเร็วลมที่ 2 ม. หรือ 0.6 m/s เมื่อไม่มีลม) ปัดเป็น 90–1,200 s ·
  จำนวนรอบ ≈ T / Δt (Δt ≈ 0.12·h หรือค่าที่วัดได้จากการคำนวณครั้งก่อน) · เวลาจริงจากความเร็วที่วัดได้ล่าสุด หรือสูตรประมาณ — ปุ่ม **ใช้ค่าแนะนำ** เติมให้
- ครบเงื่อนไขแล้วกด **คำนวณต่อ** = เดินต่ออีกเท่าค่าตั้งต้น · ผลเป็นค่าเฉลี่ย 20 s สุดท้ายเสมอ — ถ้ายังไม่ลู่เข้า หน้าผลลัพธ์บอกไว้
- แถบสถานะแสดงความคืบหน้า (รอบ x / N, t / T s หรือเวลาที่ใช้ / ที่ตั้ง) · แผงคุณภาพแสดงเงื่อนไขหยุด จำนวนรอบ และเวลาที่ใช้ · Batch ใช้เงื่อนไขเดียวกันทุก case

### ความเร็วและหน่วยความจำ

ลูปหนักทั้งหมด (advection, turbulence, diffusion, projection/SOR, การพาอุณหภูมิ, residual) อยู่ใน `src/kernels.c`
คอมไพล์เป็น WebAssembly สองแบบและฝังไว้ใน `src/kernels-wasm.js`

- **หลายเธรด** — ทุกลูปแบ่งตามชั้น k ให้เธรดละช่วง เธรดช่วยงานเป็น Web Worker บนหน่วยความจำร่วม
  (SharedArrayBuffer + atomics) ใช้ทุกแกนของเครื่อง (เว้นหนึ่งแกนให้หน้าจอเมื่อมีมากกว่า 4 แกน, สูงสุด 16 เธรด)
  ผลรวมและค่าสูงสุดเก็บแยกตามชั้นแล้วรวมตามลำดับเดิมเสมอ ผลจึง **ตรงกันทุกบิตไม่ว่าจะใช้กี่เธรด**
  (`node tools/selftest.mjs rooftop 0.35 10 --compare` ตรวจให้)
  เบราว์เซอร์ให้ใช้หน่วยความจำร่วมเฉพาะหน้าที่เป็น cross-origin isolated: เมื่อเปิดผ่าน http(s)
  service worker `coi-sw.js` จะเติมส่วนหัว COOP/COEP ให้เองแล้วโหลดหน้าใหม่หนึ่งครั้ง ไม่ต้องตั้งค่าเซิร์ฟเวอร์
  เปิดไฟล์ด้วย `file://` ทำไม่ได้ จึงคำนวณเธรดเดียว
- **หน่วยความจำ ≈ 75 ไบต์ต่อเซลล์** (เดิม 112 + สำเนานอก WebAssembly อีก 16): ฟลักซ์ของการพาอุณหภูมิส่งต่อผ่านบัฟเฟอร์
  ขนาดหนึ่งระนาบแทนอาร์เรย์สะสมเต็มกริด, ความเร็วที่กำหนดที่ขอบเก็บเป็นรายการเฉพาะหน้า, บัฟเฟอร์ความเร็วสลับแทนการคัดลอก
  รวมกับเมชที่เล็กลง ตัวอย่างดาดฟ้าที่เซลล์ 0.10 ม. ใช้ราว 64 MB จากเดิมราว 550 MB — เพดาน 4 GB ของ WebAssembly
  จึงรองรับงานที่ใหญ่กว่าเดิมมาก
- เมชใหญ่ส่งสนามค่าไปแสดงผลห่างขึ้น (ราว 0.4 วินาทีต่อล้านเซลล์) ไม่ให้การคัดลอกถ่วงการคำนวณ

### GPU (`src/gpu-solver.js`)

เครื่องคำนวณแบบ GPU เป็น solver ชุดเดียวกันที่เขียนเป็น compute shader (WGSL) ของ WebGPU — สมการ กริด เงื่อนไขขอบ

จึงแสดงช่องกรอกและตาราง capacity เทียบ T ลมเข้า) · ค่าระหว่างจุดตารางเทียบเส้นตรง · ชุดผสมที่เกิน 60 HP (62 – 78 HP) ใช้ตารางของแต่ละโมดูล ·
capacity % เทียบค่าที่ 35 °C ของ combination เดียวกัน · ความร้อนที่ระบายทิ้ง = TC + PI จากตาราง
VRV IV S: ตาราง Cooling Capacity RXMQ4AVE, RXMQ5/6BVM (EDTRMT332049) — อากาศภายนอก 10 – 39 °CDB, คอยล์เย็น 19 °CWB, Capacity ratio 50 – 130 %
VRV S Hi: ตาราง Cooling Capacity RSUQ7/8/9AYM (EDTRMT332104) — อากาศภายนอก 10 – 45 °CDB, คอยล์เย็น 19 °CWB, Capacity ratio 30 – 130 %
และ RSUQ4/5/6AVMS (EDTRTH332028) · ทั้งสองซีรีส์ใช้แบบเดียวกับ VRV 6A (ค่าเริ่มต้น 100 %)
T ลมเข้าเกินช่วงตาราง = **Estimate (ไม่ได้อ้างอิงจาก Engineering Data)** — แสดงป้ายกำกับในแผงคุณสมบัติ ตารางผลลัพธ์ ป้ายบน 3D และ CSV
· ประเมินแยกรายรุ่นจากเส้นแนวโน้มของตารางรุ่นนั้นเอง: เส้นตรง least-squares ผ่าน 6 จุดสุดท้ายของตาราง (อุณหภูมิสูงสุด) ต่อจากจุดสุดท้าย
  TC = ค่าต่ำกว่าระหว่างเส้นของ combination ที่เลือก กับเส้นของ combination 130 % (capacity สูงสุดของคอยล์ร้อน) · PI = เส้นของ combination ที่เลือก
· แผงคุณสมบัติแสดงกราฟ capacity เทียบ T ลมเข้า (เส้นทึบ = ตาราง, เส้นประ = Estimate)
ส่วน EER 3.5 ของ VRV รุ่นอื่น และ capacity ลดลง 2 %/°C (รุ่นที่ไม่มีตาราง) เป็นค่าประมาณ แก้ได้ในโปรแกรม
ผลใช้เปรียบเทียบผังการวางเครื่อง ไม่ใช่ผลรับรองทางวิศวกรรม
