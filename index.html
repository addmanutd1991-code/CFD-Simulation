    หมายเหตุ

    จำลองการไหลของลมร้อนจากคอยล์ร้อน Daikin VRV (6A / IV S / S Hi) และ Split type ในลานวางเครื่อง — หาการวนกลับของลมร้อน (hot-air recirculation) อุณหภูมิลมเข้าคอยล์แต่ละเครื่อง และผลต่อ capacity

    ใช้งานอย่างไร

    1. วางแบบ — เลือก CDU ที่แถบเครื่องมือด้านซ้าย แล้วคลิกบนพื้นเพื่อวางเครื่อง (คลิกต่อได้หลายตัว, Esc เพื่อจบ) · ผนัง/louver คลิกจุดเริ่มแล้วคลิกจุดถัดไป ลากต่อเป็นแนวรอบลานได้ (กด Shift ล็อกแนวตรง, ดับเบิลคลิกหรือ Esc เพื่อจบ, คลิกกลับจุดแรกเพื่อปิดรอบ) · อาคาร คลิกมุมหนึ่งแล้วคลิกมุมตรงข้าม · พื้น/หลังคา คลิกสองมุมเพื่อวางแผ่นพื้นยกหรือหลังคา แล้วตั้งระดับความสูง ความหนา และ % ช่องเปิด (ตะแกรง) ที่แผงด้านขวา · ระหว่างลากผนัง พิมพ์ตัวเลขแล้วกด Enter เพื่อกำหนดความยาวช่วงนั้นตามทิศเมาส์ · ปุ่มเล็กกลุ่ม แก้ไข บนแถบซ้าย: Move, Copy, Offset, Mirror, Rotate และ Pull (ยืด/หดผนัง louver อาคาร หรือพื้น-หลังคา: คลิกปลายหรือด้านที่จะขยับ แล้วคลิกตำแหน่งใหม่หรือพิมพ์ระยะ — ด้านตรงข้ามอยู่กับที่)
    2. ปรับแต่ง — คลิกเลือกวัตถุ แล้วแก้ค่าที่แผงด้านขวา: หมวดและรุ่นเครื่อง (VRV: 6A / IV S / S Hi · Split type: FTKB-A) ทิศหน้าเครื่อง ความสูงฐาน Hood (VRV 6A: แบบตรงหรือท่อโค้ง 90° กำหนดความสูง ระยะยื่น และทิศปากลม) · รุ่นเป่าหน้า (VRV IV S / S Hi / Split): ทิศทางลมร้อนออกจากเครื่อง ตรงหรือเบี่ยง 45° ขึ้น/ลง/ซ้าย/ขวา และความยาว Hood ความสูงและ % พื้นที่เปิดของ louver ความยาวผนัง (พิมพ์ค่าได้ทันที) ฯลฯ ลากวัตถุบนพื้นเพื่อย้าย (ขยับทีละ 0.1 ม., กด Alt ค้างเพื่อวางละเอียด 1 ซม.)
    3. คำนวณ — ตั้งอุณหภูมิอากาศภายนอก ลม และขนาดเซลล์ที่แท็บ ตั้งค่า ของแผงด้านขวา แล้วกด คำนวณ มุมขวาบน โปรแกรมจะหยุดเองเมื่อผลนิ่ง หรือครบเวลาจำลองสูงสุด ระหว่างคำนวณจะเห็นผลเปลี่ยนแบบสด
    4. อ่านผล — หน้า ผลลัพธ์ มีตารางแสดงอุณหภูมิลมเข้าคอยล์ของแต่ละเครื่อง ΔT เทียบอากาศภายนอก สัดส่วนลมวนกลับ และ capacity ที่เหลือ เลื่อนระนาบหน้าตัดโดยลากปุ่มกลมบนขอบระนาบ ชี้เมาส์บนระนาบเพื่ออ่านค่า ณ จุดนั้น (แสดงที่แถบสถานะด้านล่าง)
    5. เปรียบเทียบ — แก้แบบ (เช่น เพิ่มท่อเป่าลม เปิด louver กว้างขึ้น ขยับเครื่อง) แล้วคำนวณใหม่ ตารางเปรียบเทียบจะเก็บผลทุกรอบไว้

    อากาศรอบลานวางเครื่องถูกแบ่งเป็นเซลล์สี่เหลี่ยม ครอบวัตถุทั้งหมดพร้อมระยะเผื่อรอบข้างและด้านบน เมชแบบ ปรับความละเอียดอัตโนมัติ ใช้เซลล์ขนาดที่เลือกเฉพาะรอบ CDU (ห่างเครื่อง 0.6 ม. และเหนือปากพัดลม 1.2 ม.) ขอบผนัง/อาคารใช้เซลล์ 2 เท่า แล้วค่อย ๆ ขยายออกไปไม่เกิน 20% ต่อเซลล์จนถึง 8 เท่า (ไม่เกิน 1 ม.) ที่ขอบโดเมน — จำนวนเซลล์ลดลงหลายเท่าโดยความละเอียดรอบเครื่องเท่าเดิม (เลือกแบบ สม่ำเสมอ ได้ถ้าต้องการเซลล์เท่ากันทั้งโดเมน) ขอบด้านข้างและด้านบนของโดเมนเปิดสู่บรรยากาศ พื้นเป็นผนังทึบ แล้วแก้สมการการไหลแบบไม่คงตัวจนเข้าสู่สภาวะคงตัว

    แบบจำลอง CDU

    แต่ละโมดูลของเครื่องเป็นกล่องทึบ มีเงื่อนไขขอบสองแบบ ซึ่งทำให้มวลอากาศเข้าเท่ากับออกทุกโมดูล

    • หน้าคอยล์ (ลมเข้า) — ด้านหลัง ซ้าย และขวา (VRV IV S / S Hi: ด้านหลังและซ้าย) ในช่วงความสูง 8–92% ของตัวเครื่อง ดูดลมด้วยความเร็วคงที่ ถ้าด้านใดถูกผนังหรือเครื่องอื่นบัง พื้นที่ที่เหลือจะดูดแทน (รายงานเป็น "คอยล์ถูกบัง %") อุณหภูมิลมเข้า Tin คือค่าเฉลี่ยของอากาศที่หน้าคอยล์ทั้งหมด
    • หน้าพัดลม (ลมเป่า) — ด้านบนเครื่อง พื้นที่ใกล้เคียงหน้าตะแกรงพัดลมจริง (0.36 ม.² ต่อใบพัด) เป่าขึ้นด้วยความเร็ว อัตราลม ÷ พื้นที่ Hood แยกรายโมดูล · Hood ตรงเป็นท่อสี่เหลี่ยมขนาดเท่าโมดูล ลมออกขึ้นทั้งหน้าตัดที่ปลาย Hood · Hood ท่อโค้ง 90°: ท่อขึ้นจากเครื่อง โค้งด้านบน แล้วยื่นแนวนอนพ้นตัวเครื่องตามระยะยื่น ลมออกแนวนอนที่ปลายท่อ (หน้าตัดสูงเท่าความลึกเครื่อง ไม่เกินความสูง Hood)
    • รุ่นเป่าหน้า (VRV IV S / VRV S Hi / Split FTKB-A) — ลมออกจากหน้ากากพัดลมด้านหน้าเครื่อง (หรือปลาย Hood สี่เหลี่ยมที่ยื่นออกไป) ทิศทางลมร้อนเบี่ยง 45° (ใบเบี่ยงลมที่ติดกับเครื่อง) ไม่มีรูปทรงในแบบจำลอง — กำหนดความเร็วตามทิศเบี่ยงเท่ากับความเร็วพุ่ง ที่อากาศชั้นแรกหน้าปากลม ลำลมร้อนจึงออกจากเครื่องเอียงราว 40–45° · ตำแหน่ง/ขนาดหน้ากากพัดลมประมาณจากแบบ Dimensions ของ catalog

    Qrej = Qrated·capF + (Qrated/EER)·powF
    Tout = Tin + Qrej / (ρ·V̇·cp)

    ความร้อนที่ปล่อยออกขึ้นกับ Tin ของเครื่องเอง จึงคำนวณใหม่ทุกสเต็ป (ป้อนกลับ): ลมร้อนวนกลับมาก → Tin สูง → capacity ลด กำลังไฟฟ้าเพิ่ม → ปล่อยความร้อนมากขึ้น ค่าเริ่มต้น Tref = 35 °C, kcap = 2%/°C, kpow = 2.5%/°C แก้ได้ที่ ตั้งค่า → ขั้นสูง

    เกณฑ์อุณหภูมิลมกลับ (สี CDU)

    • เขียว — อุณหภูมิลมกลับที่ไม่เกิน 40 องศาเซลเซียส คอยล์ร้อนสามารถระบายความร้อนได้ เป็นอุณหภูมิลมกลับที่ Daikin แนะนำ
    • เหลือง — อุณหภูมิลมกลับที่อยู่ระหว่าง 40–46 องศาเซลเซียส คอยล์ร้อนสามารถทำงานได้ แต่ประสิทธิภาพการทำงานของเครื่องปรับอากาศจะลดลง
    • แดง — อุณหภูมิลมกลับที่เกิน 46 องศาเซลเซียส คอยล์ร้อนไม่สามารถระบายความร้อนได้ ควรปรับเปลี่ยนลักษณะการวางคอยล์ร้อน

    เกณฑ์ 40 / 46 °C เป็นค่าเริ่มต้น ปรับได้ที่ "สี CDU ตาม T ลมเข้า" ในแท็บ แสดงผล ของแผงด้านขวา

    เกณฑ์หยุดคำนวณและคุณภาพ

    • คำนวณต่อไปจนกว่าจะลู่เข้า โดยต้องผ่านทุกข้อต่อเนื่องกัน 6 ครั้ง (ตรวจทุก 0.5 วินาทีจำลอง): เวลาจำลอง ≥ 60 s · ค่าเฉลี่ย 10 s ล่าสุดของ T ลมเข้าทุกโมดูลต่างจาก 10 s ก่อนหน้าไม่เกิน ±0.05 °C · สมดุลพลังงาน (ความร้อนออกจากโดเมน + การสะสม) ÷ (ความร้อนที่ CDU ปล่อย) 95–105% · ความคลาดเคลื่อนมวล ≤ 1%
    • กราฟ residual (มวล โมเมนตัม พลังงาน) แสดงแนวโน้มแบบ CFX แต่ไม่ใช้ตัดสิน เพราะลมร้อนกระเพื่อมตลอดเวลา residual จึงไม่ลงถึงศูนย์
    • เพดานเวลา (ค่าเริ่มต้น 1,800 s) มีไว้กันกรณีที่ไม่มีวันนิ่ง เช่น ปิดขอบทุกด้าน — ถ้าถึงเพดาน กดคำนวณต่อได้
    • ความคลาดเคลื่อนของมวล = RMS ของ ∇·u หลัง projection เทียบความเร็วสูงสุด ควรต่ำกว่า 1%

    เลือกขนาดเซลล์

    ตะแกรงพัดลมหนึ่งใบกว้างราว 0.6 ม. ที่เซลล์ 0.5 ม. พัดลมถูกแทนด้วยเซลล์เพียง 1–2 เซลล์ ลำลมจะกว้างและช้ากว่าจริง จึงเหมาะกับการร่างผังเท่านั้น ใช้ 0.35 ม. สำหรับเปรียบเทียบทางเลือก และสรุปผลด้วย 0.25 ม. วิธีตรวจง่าย ๆ คือคำนวณซ้ำด้วยเซลล์เล็กลงหนึ่งขั้น ถ้า ΔT ของเครื่องที่แย่ที่สุดเปลี่ยนไม่มาก ผลใช้ได้ (ตารางเปรียบเทียบเก็บผลทั้งสองรอบให้ดู)

    เมชปรับความละเอียดอัตโนมัติ

    ขนาดเซลล์ที่เลือกคือขนาดของเซลล์ รอบเครื่อง — ส่วนที่กำหนดความแม่นยำของ T ลมเข้า:

    • รอบ CDU 0.6 ม. และเหนือปากพัดลม/ท่อเป่าลม 1.2 ม. ใช้เซลล์ขนาดที่เลือก วางบนแลตทิซเดียวกับเมชสม่ำเสมอ ตัวเครื่อง ผนัง และช่องว่างรอบเครื่องจึงถูกแทนด้วยเซลล์ชุดเดียวกัน
    • ขอบผนัง louver อาคาร และแผ่นพื้นที่อยู่ห่างเครื่องไม่เกิน 1 ม. ใช้เซลล์ขนาดที่เลือกเช่นกัน ที่ไกลกว่านั้นใช้ 2 เท่า
    • เครื่องที่ถูกล้อมด้วยของที่สูงกว่า (ช่องแคบระหว่างอาคาร คอกผนังสูง ใต้หลังคา ในระยะ 3 ม.) คงเซลล์ละเอียดในแนวดิ่งขึ้นไปถึงยอดสิ่งที่ล้อม เพราะลมร้อนวนกลับลงมาในช่องนั้น
    • ที่เหลือค่อย ๆ ขยายไม่เกิน 20% ต่อเซลล์ จนถึง 8 เท่าของขนาดที่เลือก (ไม่เกิน 1 ม.) ที่ขอบโดเมน

    จำนวนเซลล์ลดลงราว 2–3 เท่าที่เซลล์ 0.25 ม. และ 4–5 เท่าที่ 0.10 ม. โดย T ลมเข้ารายเครื่องต่างจากเมชสม่ำเสมอขนาดเซลล์เดียวกัน ไม่เกินราว 0.1–0.2 °C ในกรณีทดสอบ (น้อยกว่าผลของการเปลี่ยนขนาดเซลล์หนึ่งขั้น) ถ้าต้องการตรวจ เลือก รูปแบบเมช → สม่ำเสมอ แล้วคำนวณซ้ำ ตารางเปรียบเทียบจะเก็บผลทั้งสองรอบ

    Simulates hot-air flow from Daikin VRV (6A / IV S / S Hi) and Split-type condensing units in an equipment yard — finds hot-air recirculation, the coil inlet temperature of each unit and the effect on capacity.

    How to use

    1. Lay out — pick CDU on the left toolbar and click the floor to place a unit (keep clicking for more, Esc to finish) · Wall/louver: click a start point, then the next points, to run walls around the yard (hold Shift to lock straight, double-click or Esc to finish, click the first point again to close the loop) · Building: click one corner, then the opposite corner · Slab/roof: click two corners to place a raised floor or roof, then set its level, thickness and % open area (grating) in the right panel · while drawing a wall, type a number and press Enter to set that segment's length along the mouse direction · the small Edit buttons on the left bar run Move, Copy, Offset, Mirror, Rotate and Pull (stretch or shrink a wall, louver, building or slab: click the end or side to move, then click the new position or type a distance — the opposite side stays put)
    2. Adjust — click an object and edit it in the right panel: category and model (VRV: 6A / IV S / S Hi · Split type: FTKB-A), unit facing, base height, hood (VRV 6A: straight or 90° elbow with height, overhang and outlet direction) · front-discharge models (VRV IV S / S Hi / Split): discharge direction straight or deflected 45° up/down/left/right, and hood length · louver height and % open area, wall length (type it directly), etc. Drag objects on the floor to move them (0.1 m steps; hold Alt for 1 cm)
    3. Run — set the ambient temperature, wind and cell size on the Setup tab of the right panel, then press Run at the top right. The program stops by itself when the result is steady or the simulated-time cap is reached. Results update live during the run
    4. Read the results — the Results page lists each unit's coil inlet temperature, ΔT above ambient, recirculation fraction and remaining capacity. Move the section plane by dragging the round handle on its edge; hover over the plane to read values at that point (shown in the status bar at the bottom)
    5. Compare — change the layout (add hoods, open the louvers, move units) and run again; the comparison table keeps every run

    What the program calculates

    The air around the yard is divided into rectangular cells covering all objects plus a margin around and above them. The adaptive mesh uses the chosen cell size only around the CDUs (within 0.6 m of a unit and 1.2 m above the fan outlet); wall/building edges use 2× cells, then cells grow by at most 20% per cell up to 8× (max 1 m) at the domain edge — several times fewer cells for the same resolution around the units (choose Uniform for equal cells everywhere). The sides and top of the domain are open to the atmosphere and the floor is a solid wall; the unsteady flow equations are then solved until a steady state is reached.

    ∂u/∂t + (u·∇)u = −∇p/ρ + ∇·(νt∇u) + g·β·(T − T∞)·ŷ − kL|u|u
    ∂T/∂t + ∇·(uT) = ∇·(αt∇T)
    ∂c/∂t + ∇·(uc) = ∇·(αt∇c)
    PartMethod
    GridStaggered (MAC) rectilinear grid with non-uniform cell widths; velocities on cell faces, pressure, temperature and tracer at cell centres — no checkerboard pressure
    Momentum advectionSemi-Lagrangian (back-tracing + trilinear), stable up to CFL 1.5
    PressureProjection: the Poisson equation is solved with Red-Black SOR, warm-started from the previous step, with the iteration count adapted to keep the mass error below 1%
    TurbulenceSmagorinsky: νt = (CsΔ)²|S| + ν0 with Cs = 0.17, ν0 = 0.002 m²/s and αt = νt/0.85
    BuoyancyBoussinesq relative to ambient, β = 1/(T∞ + 273.15)

    LouverPorous medium: Δp = K·½ρu², K = (1/(Cd·φ) − 1)², Cd = 0.6, φ = % open area

    CDU model

    Each module of a unit is a solid box with two boundary conditions, so that the air mass entering equals that leaving for every module.

    • Coil faces (inlet) — rear, left and right (VRV IV S / S Hi: rear and left) over 8–92% of the unit height, drawing air at a constant speed. If a side is blocked by a wall or another unit, the remaining area draws the air instead (reported as "Coil blocked %"). The inlet temperature Tin is the average of the air over all coil faces
    • Fan face (discharge) — the top of the unit, with an area close to the real fan grille (0.36 m² per fan), blowing upward at airflow ÷ area. Hoods are per module · a straight hood is a rectangular duct the size of the module, discharging upward over its whole section · a 90° elbow hood rises from the unit, bends at the top, then extends horizontally past the unit by the overhang; air leaves horizontally at its end (opening as tall as the unit depth, but no more than the hood height)
    • Front-discharge models (VRV IV S / VRV S Hi / Split FTKB-A) — air leaves the fan grille at the front of the unit (or the end of a square hood extending from it). A 45° deflection (a deflector fitted to the unit) has no geometry in the model — the deflected velocity is imposed, equal to the jet speed, on the first layer of air in front of the outlet, so the plume leaves at about 40–45° · grille position/size are estimated from the catalogue dimension drawings
    capF = 1 − kcap·(Tin − Tref)    powF = 1 + kpow·(Tin − Tref)
    Qrej = Qrated·capF + (Qrated/EER)·powF
    Tout = Tin + Qrej / (ρ·V̇·cp)

    The rejected heat depends on the unit's own Tin, so it is recomputed every step (feedback): more recirculation → higher Tin → less capacity and more power → more heat rejected. Defaults: Tref = 35 °C, kcap = 2%/°C, kpow = 2.5%/°C, editable under Setup → Advanced.

    Return-air temperature criteria (CDU colours)

    • Green — return air up to 40 °C: the condensing unit rejects heat normally. This is the return-air temperature Daikin recommends
    • Yellow — return air between 40–46 °C: the unit still operates, but the air conditioner loses efficiency
    • Red — return air above 46 °C: the unit cannot reject heat. The layout should be changed

    40 / 46 °C are defaults; change them under "CDU colour by inlet T" on the Display tab of the right panel.

    ValueMeaning

    Stopping criteria and quality

    • The run continues until converged: all of the following must pass 6 times in a row (checked every 0.5 simulated seconds): simulated time ≥ 60 s · the latest 10 s mean inlet T of every module differs from the previous 10 s by no more than ±0.05 °C · energy balance (heat leaving the domain + storage) ÷ (heat released by the CDUs) within 95–105% · mass error ≤ 1%
    • The residual chart (mass, momentum, energy) shows trends as in CFX but is not used for the decision, because the plume keeps fluctuating and residuals never reach zero
    • The time cap (default 1,800 s) guards against cases that never settle, e.g. all boundaries closed — if it is reached you can continue the run
    • Mass error = RMS of ∇·u after projection relative to the maximum speed; it should stay below 1%

    Choosing the cell size

    One fan grille is about 0.6 m wide. With 0.5 m cells a fan is represented by only 1–2 cells and the jet becomes wider and slower than reality, so that size is for sketching only. Use 0.35 m to compare options and 0.25 m for final results. A simple check: repeat the run one size finer; if the ΔT of the worst unit hardly changes, the result is usable (the comparison table keeps both runs).

    Adaptive mesh

    The chosen cell size is the size of the cells around the units — the part that determines the accuracy of the inlet T:

    • Within 0.6 m of a CDU and 1.2 m above the fan/hood outlet the chosen size is used, on the same lattice as the uniform mesh, so units, walls and the gaps around the units are represented by the same cells
    • Edges of walls, louvers, buildings and slabs within 1 m of a unit also use the chosen size; farther away, 2×
    • Units surrounded by taller things (a gap between buildings, a tall enclosure, under a roof within 3 m) keep fine cells vertically up to the top of the enclosure, because the hot air recirculates down that shaft
    • Elsewhere cells grow by at most 20% per cell up to 8× the chosen size (max 1 m) at the domain edge

    The cell count drops about 2–3× at 0.25 m and 4–5× at 0.10 m, with per-unit inlet T differing from the uniform mesh of the same cell size by no more than about 0.1–0.2 °C in the test cases (less than the effect of one cell-size step). To check, choose Mesh type → Uniform and run again; the comparison table keeps both runs.

    Calculation speed — choosing the compute device

    Choose it in the right panel under Setup → Compute device before pressing Run. The status bar at the bottom shows what is actually in use.

    OptionFile opened by double-click (file://)Opened via http:// or https://
    CPU — WebAssembly1 threadAll cores; results are bit-identical regardless of thread count
    GPU — graphics card (WebGPU)AvailableAvailable

    GPU needs Chrome / Edge 113 or later and a supported graphics driver. It computes in 32-bit floats, so results differ from the CPU in the last digits (per-unit inlet T agrees to two decimals in the test cases) and uses about 112 bytes of GPU memory per cell. It pays off with large meshes and discrete graphics cards. If GPU setup fails, the program falls back to the CPU and tells you.

    Why multi-threaded CPU needs http(s) — threads must share one block of memory (SharedArrayBuffer). Browsers enable that only for pages whose server sends the COOP/COEP security headers (a post-Spectre measure). A page opened from a local file has no server and therefore no headers, and no browser setting can turn it on. The options are:

    1. A local server: install Node.js and run npm run serve in the program folder, then open http://localhost:8000/dist/cdu-airflow-cfd.html (accepts connections from this machine only; works offline)
    2. Any other file server, e.g. python -m http.server 8000 in the dist folder — the coi-sw.js file next to the HTML file adds the headers itself and reloads the page once
    3. Put both files of the dist folder on a web host (GitHub Pages or an intranet site) and open it via https:// — the calculation still runs entirely on the user's machine; no project data is sent to the server

    Or switch the compute device to GPU, which has no such requirement. CPU memory use is about 75 bytes per cell.

    Limitations

    • This is a simulation for comparing equipment layouts, not an engineering certification. Use it together with the manufacturer's installation clearances
    • The airflow simulation is a computer experiment only. It is intended to help prevent, or find solutions to, heat-rejection problems; it is not the actual air condition around the CDUs
    • Wind direction depends on the season and the time of day, whereas the CFD uses a single direction. A mock-up installation should therefore be tested to verify the CFD results
    • The turbulence model is a coarse LES (Smagorinsky) without wall functions, and radiation from hot roofs/walls is not included
    • kW, airflow, dimensions and combinations of each model come from catalogues EDTRTH342529A (VRV 6A), EDTRMT332049 (VRV IV S), EDTRTH332028A, EDTRMT332104A (VRV S Hi) and EDTTH042558 (Split FTKB-A — EER uses the catalogue COP), but EER (3.5) and the capacity-versus-temperature relation are estimates — editable under Setup → Advanced, and the airflow of each unit can be overridden
    • Oblique walls/buildings are represented by stair-stepped cells; anything smaller than a cell is rounded to one cell
    • Wind through the domain is steady, without atmospheric turbulence. The no-wind case (0 m/s) is usually the worst
